    着色器

    着色器（Shader） 是跑在显卡上的一小段 GLSL 程序。引擎把画面交给它，它就按你写的规则，逐像素决定每个点最终是什么颜色。

    在 LÖVE 里，绝大多数时候你只需要写一个 片元着色器（effect 函数）就够了 —— 它就像一张"每个像素都要过一遍的滤镜"。

    本篇讲的是 引擎里常规的 Shader 写法。如果你想直接搬运网上现成的效果，看 ShaderToy 转化库 ；如果你想了解屏幕着色器"乒乓法"的绘制流程，看 画布与屏幕 ；底层的 LÖVE 绘图 API 清单在 与LOVE开发 → 图像绘制 。

    最小的一个 Shader¶

    一个能跑的最小 Shader 就是这么一个函数：

    vec4 effect(vec4 color, Image tex, vec2 tex_coords, vec2 screen_coords) {
    vec4 pixel = Texel(tex, tex_coords);
    return pixel * color;
}

    这段代码的效果是 什么都不做 —— 它把贴图原样取出来、乘上绘制颜色、再返回。理解这一句，就理解了 Shader 的全部骨架。

    effect 的四个参数¶

    参数 类型 含义
    color vec4 当前的绘制颜色，来自 setColor 或贴图的 color / alpha
    tex Image 正在被绘制的纹理 —— 通常就是那张图本身
    tex_coords vec2 纹理 UV，范围 0~1 ，按被绘制图形计算
    screen_coords vec2 屏幕坐标，单位是像素

    它的 返回值 就是这个像素的最终颜色（包含 alpha），直接决定屏幕上看到的东西。

    采样纹理必须用 Texel

    LÖVE 里取纹理颜色的函数是 Texel(tex, uv) ，不是标准 GLSL 的 texture() 。写错了编译会直接失败。

    tex_coords 是图形自己的 UV，不是屏幕坐标

    一张铺满全屏的图，tex_coords 才刚好等于"屏幕坐标归一化后的值"。 把它挂在一张 32×32 的小图上，tex_coords 依然只在 0~1 之间跑 —— 效果会被"压缩进那 32×32 的区域"，而不是铺满屏幕。 这一点和 ShaderToy 的 fragCoord 有本质区别（详见 ShaderToy 那篇的说明）。

    想改的不是颜色，而是形状？¶

    那要用 顶点着色器 入口 position ，它决定每个顶点画到哪：

    vec4 position(mat4 transform_projection, vec4 vertex_position) {
    return transform_projection * vertex_position;
}

    顶点入口用得少得多。日常做特效，先盯着 effect 就够了。

    uniform：让 Lua 把参数喂进去¶

    着色器本身是"死"的，想让它动起来，就得靠 uniform —— 外部每帧送进去的参数。

    GLSL 侧用 extern 声明：

    extern number time;        // LÖVE 里 number 等价于 float
extern vec2 amplitude;
extern Image mask;

    Lua 侧用 send 赋值：

    shader:send("time", 1.5)
shader:send("amplitude", {0.02, 0.05})
shader:send("mask", someImage)

    类型对照¶

    GLSL 声明 Lua 里 send 的值
    extern number x; 一个数字
    extern vec2 / vec3 / vec4 v; {1, 2} / {1, 2, 3} / {1, 2, 3, 4}
    extern Image img; 一张 Image / Canvas
    extern mat4 m; 矩阵（少见）
    extern bool b; true / false

    number 就是 float

    LÖVE 里 number 是 float 的别名，引擎自带的着色器两种写法都在用。写 float 也完全没问题。

    先查再发，避免静默失败

    shader:hasUniform("time") 可以判断某个 uniform 是否存在。 名字拼错时 LÖVE 不一定报错，效果却"纹丝不动" —— 先用它自检一下最省事：

    if shader:hasUniform("time") then
    shader:send("time", t)
end

    三种用法，由小到大¶

    用法 怎么写 适合
    贴图级 spr:SetShaders({shader}) 给某一张图 / 某个 sprite 加特效
    全局屏幕 Global.SetVariable("ScreenShaders", {shader}) 整屏滤镜（做画面氛围）
    完全自定义 SE.graphics.setShader(shader) + 自己 setCanvas 想要完全控制绘制时机与目标
    • 贴图级的方法清单（ SetShaders / AddShader / InsertShader / RemoveShader / ClearShaders ）见 贴图 → 常用方法 。 挂多个着色器时，引擎会在两张和贴图同尺寸的临时画布之间 乒乓 ，逐个叠加，所以效果会按列表顺序依次作用。
    • 全局屏幕的 ScreenShaders 走的是主画布 ↔ 中间画布的乒乓流程，原理在 画布与屏幕 里讲透了。
    • 最底层的 newShader / setShader / validateShader 全部包在 SE.graphics 下，清单见 图像绘制 。

    最快写出第一个案例¶

    三步：写一个 .glsl 文件 → 写一个测试场景 → 把它设成启动场景。

    第一步：新建 Scripts/Shaders/MyWave.glsl¶

    extern number time;
extern number amplitude;

vec4 effect(vec4 color, Image tex, vec2 tex_coords, vec2 screen_coords) {
    // 按 y 轴做正弦横向偏移：越往下，横向扭动越明显
    vec2 uv = tex_coords;
    uv.x += sin(uv.y * 12.0 + time * 3.0) * amplitude;

    vec4 pixel = Texel(tex, uv);
    return pixel * color;
}

    第二步：新建测试场景 Scripts/Scenes/TEST/scene_my_shader.lua¶

    local scene = {}

-- 编译一次，缓存住。千万别每帧 newShader（那等于每帧重新编译）
local shader = SE.graphics.newShader("Scripts/Shaders/MyWave.glsl")

-- 一张铺满屏幕的白图，用来"承载"整屏特效
local bg = Sprites.CreateSprite("px.png", 0)
bg:Scale(CANVAS_WIDTH, CANVAS_HEIGHT)
bg:SetShaders({shader})

local t = 0

function scene.update(dt)
    t = t + dt
    shader:send("time", t)          -- 每帧喂时间，动画才会动
    shader:send("amplitude", 0.02)
end

function scene.draw() end

function scene.clear()
    Layers.clear()
end

return scene

    第三步：让它一启动就跑¶

    在 conf_pure.lua 里把 FirstRoom 指向它：

    Global.SetVariable("FirstRoom", "TEST.scene_my_shader")

    进游戏应该能看到整个屏幕在轻微地左右摆动。把 amplitude 从 0.02 改成 0.2 ，效果立刻放大十倍 —— 这就是调 Shader 最爽的地方：改一个数，立刻看到结果。

    两种加载方式

    • SE.graphics.newShader("Scripts/Shaders/MyWave.glsl") —— 直接给文件路径。
    • ImportFile("MyWave", "shader") —— 只给名字，引擎会自己去 Scripts/Shaders/ 找 .glsl ，并且 编译失败时抛出带路径的明确报错，排错更方便。

    也可以直接把 GLSL 代码当字符串传进去，省掉一个文件（ShaderToy 转化库 就是这么干的）。

    编译失败是抛错，不是返回 nil

    Shader 语法错会让 newShader 直接抛错。加载不确定来源的着色器时包一层 pcall ， 否则整个场景都起不来。想提前单独检查语法，用 SE.graphics.validateShader(code) 。

    引擎自带的 7 个着色器¶

    Scripts/Shaders/ 里已经躺着 7 个能直接用的着色器。练习的最省力起点，就是把它们拆开改。

    文件 做什么 关键 uniform
    ColorFilter.glsl 灰度 + 染色（mix 控制灰度程度） grayscale tint_color
    Gradiant.glsl 四角颜色渐变，可旋转角度 topLeftColor 等四角 + angle
    WaveDistort.glsl 正弦波形扭曲，横竖两个方向 time amplitude frequency speed tex_size
    Glow.glsl 采四周邻居算亮度差，边缘发光 glow_color glow_intensity threshold tex_size
    Dust.glsl 扫描线溶解淡出（用了 if 分支与噪声） dt scan_y 等
    FourPoint.glsl 四点形变，用逆双线性插值解 UV，越界 discard p1 ~ p4
    PixelSmooth.glsl 用 dFdx/dFdy 做像素平滑，专治旋转锯齿 texture_pixel_size

    读它们的顺序建议：ColorFilter → WaveDistort → Glow → FourPoint 。 前三个是"改颜色 / 改 UV / 采邻居"，覆盖了 90% 的日常需求；FourPoint 是几何级别的，当数学题看。

    后续怎么练¶

    Shader 的学习曲线是"开头陡、后面平"：先抄、再改、最后自己写公式。

    阶段一：改常数（几乎不用懂数学）¶

    把现成着色器的 uniform 推到极端，看现象：

    • 把 ColorFilter 的 grayscale 从 0 慢慢调到 1 ，看画面变灰。
    • 把 Glow 的 threshold 调高 / 调低，看发光区域变大变小。
    • 把 WaveDistort 的 amplitude 从 0 拉到 0.5 ，看画面被拧成什么样。

    阶段二：改公式（开始碰数学）¶

    • 把 sin(...) 换成 cos(...) 、abs(sin(...)) 、sqrt(...) ，看波形怎么变。
    • 把 WaveDistort 里两条轴的 sin 频率改成不同的数，做出"水波"和"抖动"的差别。
    • 把 uv.x += 改成 uv.y += ，理解"横向扭曲"和"纵向扭曲"的对称性。

    阶段三：从零写小效果¶

    每个都只做 一件事，挂在全屏白图上跑：

    目标 思路提示
    染色 pixel.rgb * vec3(1.0, 0.5, 0.5)
    灰度 dot(pixel.rgb, vec3(0.299, 0.587, 0.114))
    反色 1.0 - pixel.rgb
    亮度 / 对比度 (pixel.rgb - 0.5) * contrast + 0.5 + brightness
    扫描线 用 tex_coords.y 配合 sin 或 step 做条纹
    径向暗角 用 distance(tex_coords, vec2(0.5)) 做中心亮、四周暗
    波纹 用 sin(distance(uv, center) * k - time) 做同心圆

    阶段四：组合与进阶¶

    • 用 SetShaders 一次挂多个着色器，体会它们 按顺序叠加 的效果。
    • 开始接触 采样邻域（像 Glow 那样取上下左右的像素）和 多次采样（模糊、描边）。
    • 想做大场面，就看 ShaderToy 转化库 ，借社区现成的代码，再回头拆解。

    推荐资源¶

    • 《The Book of Shaders》 （ thebookofshaders.com ）—— 讲概念最好的免费教程，重点看"颜色 / 形状 / 随机 / 噪声"几章。注意它的示例是 WebGL 写法，搬到 LÖVE 时要换成 effect + Texel 。
    • ShaderToy —— 海量现成效果，配合引擎的转化库直接用。
    • 引擎自带的 7 个着色器 —— 最好的"本地范本"，因为它们的写法就是本项目要长期维护的风格。

    性能与坑¶

    千万别每帧创建着色器

    newShader 会触发 GPU 编译，非常贵。正确做法是在场景加载时编译一次、模块顶层缓存住， 每帧只 send uniform。send 很便宜，随便调。

    画完记得还原

    SE.graphics.setShader(shader) 会一直生效到下一次 setShader() 为止。 用完立刻还原，否则会污染后面所有绘制：

    SE.graphics.setShader(shader)
-- ... 你的绘制 ...
SE.graphics.setShader()      -- 还原

    全屏 + 邻域采样 = 贵

    effect 是 每个像素都要跑一遍 的。Glow 这种一次采 5 个点的着色器， 在整屏像素上就是 5 倍采样量；再叠几个 pass 就是乘法级增长。 手机上尤其要克制 —— 这也是引擎给 PixelSmooth 做了缓存优化、而不是每帧 setFilter 的原因。

    只认 GLSL ES 1.0

    没有 switch 、没有 #version 300 es 、不能动态索引数组 uniform。 从网上抄代码时先确认版本，具体限制与"哪些写法一定编译失败"列在 ShaderToy 转化库 的坑一节。

    关于 Y 轴

    屏幕坐标 y 向下为正。写"从下往上"的数学时，第一反应对不上是正常的 —— 把公式里的符号翻一下，或先画一条参考线确认方向。

    用 validateShader 提前查错

    改完 GLSL 不必每次都进游戏才发现错误：SE.graphics.validateShader(code) 只做编译检查、 不真正替换当前着色器，适合在工具或启动时先跑一遍。
