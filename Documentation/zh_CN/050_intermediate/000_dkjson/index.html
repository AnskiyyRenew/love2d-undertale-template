    JSON 库

    引擎自带两个 JSON 库：底层的 dkjson 和套在它外面的 SafeJson。

    库 路径 用途
    dkjson Scripts/Libraries/Utils/dkjson.lua 纯编解码，快、无限制，自己写的、可信的数据用它
    SafeJson Scripts/Libraries/Utils/SafeJson.lua 在 dkjson 外面加了三道安检，用于外部传入的、不可信的 JSON

    引擎自己就在用它们：

    位置 用哪个 干什么
    Scripts/Libraries/Global.lua dkjson 全局存档 global_save.json 的读写
    Scripts/Libraries/Localize.lua dkjson 读取 Localization/*.json 翻译表
    Scripts/Libraries/GamejoltAPI.lua dkjson 解析网络接口返回值
    Scripts/Libraries/Controller/VirtualKeyboard.lua SafeJson 玩家自定义的虚拟键盘布局文件

    导入方式

    两个库都在 Utils 子目录下，必须带前缀，写成 ImportFile("Utils.dkjson") 。 ImportFile("dkjson") 会找不到文件。

    dkjson¶

    local json = ImportFile("Utils.dkjson")

    解码¶

    local data, pos, err = json.decode(str, startPos, nullValue)
    • str JSON 字符串。
    • startPos 从哪个字符开始解析，默认 1 。几乎不用传。
    • nullValue JSON 里的 null 要解码成什么，默认 nil 。
    • 返回值是 三个： data, pos, err 。
    情况 返回值
    成功 data = 表/数字/字符串/布尔， pos = 解析结束位置， err = nil
    失败 data = nil ， pos = 出错位置， err = 错误描述（包含行号）

    一定要判第三个返回值

    local data = json.decode(str) 在 JSON 写错时 data 是 nil 但不报错， 后面直接 data.xxx 才会炸，而且报错地点离真正的原因很远。老老实实写：

    local data, pos, err = json.decode(text)
if (err) then
    print("JSON 解析失败（第 " .. pos .. " 个字符附近）：" .. err)
    return
end

    编码¶

    local text = json.encode(value, options)
    • value 任意 Lua 值，通常是表。
    • options 可选表，常用的两项：
    键 效果
    indent 为 true 时输出带缩进换行的可读格式；不写就是一行压缩格式
    keyorder 字符串数组，指定对象里键的输出顺序

    encode 出错是直接抛错，不是返回 nil

    dkjson 内部写的是 error(msg, 2) 。遇到循环引用、函数、userdata 这类无法编码的值， json.encode 会直接中断整个调用栈。写存档时请包一层 pcall ：

    local ok, text = pcall(json.encode, myTable)
if (not ok) then
    print("编码失败：" .. tostring(text))
    return
end

    表怎么变成数组还是对象¶

    JSON 分不清 Lua 的"数组"和"字典"，dkjson 的判断规则是：

    你的表 编码结果 说明
    {1, 2, 3} [1,2,3] 整数键 1..n 连续 → 数组
    {a = 1} {"a":1} 有非整数键 → 对象
    {[1] = "a", [3] = "c"} ["a",null,"c"] 断档也算数组，缺的那格补 null （不是退化成对象）
    {} {} 空表是对象
    {1, 2, x = 3} {"1":1,"2":2,"x":3} 混了非整数键 → 对象

    规则本身是 isarray(tbl) （ dkjson.lua 第 81 行）：只要所有键都是 >= 1 的整数就当作数组，然后按最大键值 max 从头循环到 max ，nil 的位置补 null 。

    唯一的例外：洞太多才退化成对象

    isarray 最后有一句：

    if max > 10 and max > arraylen and max > n * 2 then
    return false -- don't create an array with too many holes
end

    翻译过来：只有当最大键超过 10、而且实际元素连最大键的一半都不到时，才当成对象编码（键会变成字符串）。 比如 {[1]="a", [50]="b"} ： max = 50 、 n = 2 、 50 > 2 * 2 ，于是退化成 {"1":"a","50":"b"} 。
    而 {[1]="a",[3]="c"} 因为 max = 3 不超过 10，仍然是数组。

    来回一趟会变形

    存进去是 [1,2,3] ，读出来还是 {1,2,3} ；
    但断档数组存进去是 ["a",null,"c"] ，读出来是 {1 = "a", 3 = "c"} —— 中间那格在 Lua 里就是不存在（ nil ）， t[2] 取到 nil ；
    只有落到上面那个"洞太多"分支对象化的，读回来键才是字符串 "1" ， t[1] 取不到，得用 tonumber(k) 兜一层。

    存档里的列表要么保证连续，要么读取时对每个键做一次 tonumber 。

    特殊值¶

    值 行为
    nil 编码为 null
    math.huge / -math.huge / NaN 编码为 null （不是报错，是静默变 null）
    函数 / userdata 编码时 error
    循环引用的表 编码时 error

    json.null 是一个特殊标记，写进表里会被编码成 null （而不是被当成空表消失）：

    local t = {name = "Sans", nick = json.null}
print(json.encode(t))   -- {"name":"Sans","nick":null}

    引擎里的真实例子¶

    Global.lua 的存档读写（简化） 
    local json = ImportFile("Utils.dkjson")
local file_name = "global_save.json"

-- 读
local contents = SE.filesystem.read(file_name)
local decoded, _, err = json.decode(contents)
if (not decoded) then
    print("存档损坏：" .. tostring(err))
end

-- 写
local encoded = json.encode(global._saveData or {})
SE.filesystem.write(file_name, encoded)

    路径是相对存档目录

    SE.filesystem.read / write 走的是 LÖVE 的存档目录（手机上是应用私有目录）， 传相对路径即可，不要传 C:\... 这种绝对路径。

    SafeJson¶

    local safejson = ImportFile("Utils.SafeJson")

    它对解析方向加了三层检查，用来处理"别人给你的 JSON"（网络返回、玩家手改的存档、导出的分享码）。

    解析¶

    local data, err, errType = safejson.parse(jsonString, options)
    • 成功： data 是解析出来的值， err 和 errType 都是 nil 。
      • 大多数情况是表，但 JSON 顶层直接是一个数字 / 字符串 / 布尔 / null 时， data 就是那个标量（ null 会解成 nil ）。所以别无条件 #data 。
    • 失败： data 是 nil ， err 是英文描述， errType 是错误类型编号。
    errType 常量名 含义
    1 MALFORMED JSON 本身语法错误（含 BOM 头）
    2 UNSAFE_KEY 键名或值命中黑名单；调试钩子检测也算这一类
    3 CIRCULAR 循环引用（目前不会出现，见下）
    4 OVER_LIMIT 超过数量/深度/长度限制

    errType == 3 是个够不着的分支

    SafeJson.lua 里 error_types.CIRCULAR = 3 只有定义，没有任何地方返回它。
    原因是 parse 走的是 dkjson 的 decode（纯文本 → 表），解码阶段根本不会产生表之间的循环引用；而编码那一侧（ encode ）压根没有安检。
    所以写 errType 判断时写下 1 / 2 / 4 就够了，3 永远命中不了。

    三道检查分别是什么¶

    顺序 检查 说明
    ① check_bom 文件带 UTF-8 BOM 头直接拒
    ② precheck_json + 黑名单扫描 在解析之前把整段文本转小写，逐条搜黑名单子串
    ③ check_object_safety 解析之后递归检查每个键和值

    ③ 的限制默认值：

    限制 默认值
    max_depth 100 层
    max_items 12000 个
    max_string_length 1e6 字符

    想改就在第二个参数里覆盖（内部用 setmetatable(options, {__index = 默认配置}) ，没写的字段自动回落）：

    local data, err, t = safejson.parse(text, {max_items = 100, max_depth = 10})

    把 enable_precheck 设为 false 可以只跳过第 ② 步的整串扫描（第 ③ 步仍会检查键名）。

    黑名单里有什么¶

    safejson.config.badwords 是一张 {["词"] = true} 的表，涵盖两类：

    • Lua 侧： __index 、 getmetatable 、 require 、 os.execute 、 io.popen 、 function 、 coroutine ……
    • Web 侧： __proto__ 、 constructor 、 prototype 、 eval 、 fetch 、 XMLHttpRequest 、 localStorage 、 javascript: 、 onload 、 iframe ……

    这些检查是为"JSON 会被喂进别的解析器或写进网页"设计的。

    编码¶

    local text = safejson.encode(value)

    encode 方向没有任何安全检查

    它只是 safejson.json.encode(value) 的转发，等价于 dkjson 的 encode ， 同样会 error 。 SafeJson 的"safe"只作用在 parse 上。

    坑¶

    黑名单是子串匹配，会误伤正常内容

    check_object_safety 用的是 lower_v:find(word, 1, true) —— 纯文本子串查找，没有词边界。 也就是说：

    • 键名 global_volume 含 global → 拒绝
    • 键名 functions 含 function → 拒绝
    • 值 "The process of..." 含 process → 拒绝
    • 值 "Import complete" 含 import → 拒绝

    对自己写的中文内容影响不大，但英文文案很容易踩到。 结论：自己生成的、可信的 JSON 一律用 dkjson，只有来源不可信时才用 safejson.parse 。

    parse 会把 \uXXXX 转义转成小写

    normalize_unicode 会先把文本里所有 \uXXXX 替换成对应字符并 :lower() ， 再交给 dkjson。所以 "\u0041BC" 会变成 "abc" —— 大小写信息丢失。 中文一般不用 \u 转义，不受影响；但含大写字母的 ASCII 字符串要注意。

    开着调试器时 parse 会失败

    anti_tamper_check 检查 debug.gethook() ，只要当前挂了调试钩子（断点调试、某些性能分析工具） 就返回 "Debug hook detected" 。调试期间如果 parse 莫名失败，先把调试器摘掉再试。

    全局内存超过 100MB 会拒绝解析

    check_resource_limits 用 collectgarbage("count") 判断，超过 100MB 直接返回错误。 大工程里这个函数可能"时好时坏"，取决于调用时机有没有刚跑完 GC。

    precheck 只扫前 max_string_length 个字符

    默认 1e6 ，基本等于全文，但如果你为了性能把它调小，超出的部分不会被扫到。

    完整例子¶

    自己写一份可读的配置文件

    local json = ImportFile("Utils.dkjson")

local config = {
    version = 3,
    player = {name = "Frisk", lv = 1, hp = 20},
    flags = {met_sans = true, spare = false}
}

local text = json.encode(config, {
    indent = true,
    keyorder = {"version", "player", "flags"}
})

SE.filesystem.write("my_config.json", text)

    读一份可能被人改过的外部 JSON

    local safejson = ImportFile("Utils.SafeJson")

local text = SE.filesystem.read("download/layout.json")
if (not text) then return end

local data, err, errType = safejson.parse(text)
if (not data) then
    -- errType: 1=语法错 2=危险内容/调试钩子 4=超限（3 目前不会出现）
    print("拒绝加载（类型 " .. tostring(errType) .. "）：" .. tostring(err))
    return
end

print("加载成功，控件数量：" .. #(data.controls or {}))
