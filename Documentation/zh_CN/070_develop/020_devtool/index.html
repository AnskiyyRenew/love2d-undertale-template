    变量调试器

    DevTool 是引擎的 运行时变量调试器 ，按 F8 会弹出一个独立的工具窗口，里面有两个标签页：

    • Tree（变量树）：把引擎内存里的对象层层展开，直接看、直接改。
    • Console（控制台）：一个沙箱 REPL，可以对着引擎全局变量执行表达式与赋值语句。

    它和 对象调试器 分工不同：对象调试器管 屏幕上的 sprite ，变量调试器管 任意表 / 字段值 。

    库路径： Scripts/Libraries/Engine/DevTool.lua

    仅开发版可用

    与对象调试器一样，DevTool 只在 _RELEASED 为 false 时加载（见 conf.lua ，由 main.lua 导入并调用 Update / Draw）。发布版里 F8 不会打开任何东西。

    依赖 SDL3

    DevTool 依赖 Scripts/Libraries/Utils/Windows.lua 创建子窗口，需要 LÖVE 12（自带 SDL3） 。若该库不可用，它会在终端打印 [DevTool] Windows.lua / SDL3 not available. 并自行停用，不影响游戏本体。

    打开与关闭¶

    按键 作用
    F8 打开 / 关闭工具窗口

    窗口在你 第一次按 F8 之前一直保持关闭 。也可以在代码里直接调用 DevTool.Toggle() 达到同样效果。

    窗口标题栏右上角有一个 KF:YES / KF:NO 指示，表示这个子窗口当前是否拿到了系统键盘焦点（见下文「键盘输入的坑」）。

    标签页：变量树¶

    进入后默认停在 Tree 页。顶部有一个 快速编辑栏 ，下方是变量树列表。树的顶层固定为这几个根节点：

    根节点 内容
    Player 玩家对象
    Battle 战斗系统
    Overworld 大地图系统
    Scenes.current 当前场景
    Global (config) 全局配置
    _G (all globals) 所有全局变量

    这些都是 实时读取 的引用，场景切换、对象被替换后会自动重新指向，不需要手动刷新。

    树上的操作¶

    • 展开 / 折叠：点击表节点的箭头或节点本身。表节点会显示子项数量，形如 table(12) 。
    • 编辑数字 / 字符串：点击这类叶子节点会进入行内编辑，改完后按 Enter 写回真实内存。
    • 切换布尔值：点击布尔叶子节点直接取反。
    • 重建子项：选中某个表节点后按 R ，会丢掉缓存重新扫描它的子项，用来刷新动态增删的容器。

    环状引用与函数

    树会自动跳过函数字段，并检测环状引用（自引用或互相引用），避免无限递归展开。

    快速编辑栏¶

    顶部的 path / value 两个输入框可以直接按路径读写，适合快速改一个深层字段：

    • 在 path 里填路径，例如 Player.hp ，按 Enter 就把当前值读进 value 框。
    • 在 value 里填新值，按 Enter 写回。
    • 按 Tab 在两个输入框之间切换，Esc 退出输入。

    路径支持点号与方括号，例如 Player.hp 、Battle.enemies[1].hp 。

    标签页：控制台¶

    Console 页是一个 沙箱 REPL ，输入一行按 Enter 执行：

    • 先尝试当作 表达式 求值，成功的话把返回值以 = 前缀打印出来，例如输入 1 + 2 会回显 = 3 。
    • 表达式不成立时，再当作 语句 执行，例如 Player.hp = 999 。

    可用的全局变量有： Player 、Battle 、Overworld 、Scenes 、Global 、_G 。

    沙箱是只读挂载，不会污染全局

    控制台通过 __index = _G 读取引擎全局，语句写入的是引擎里那些表本身（所以 Player.hp = 999 真的会改到玩家），但沙箱环境自己不会往 _G 里塞新的全局变量。

    在这个沙箱里调用 print(...) 也会被 重定向到控制台 ，而不是终端，方便你插入调试输出。

    滚动滚轮可以回看历史输出；按 Esc 清空当前输入。

    快捷键速查¶

    位置 按键 作用
    全局 F8 打开 / 关闭工具窗口
    标签页 点击标题栏，或按 T / C 切到 Tree / Console
    快速编辑栏 Enter 在 path 框读值、在 value 框写值
    快速编辑栏 Tab 在 path / value 框之间切换
    快速编辑栏 Esc 退出输入
    树上 R 重建选中节点的子项
    树上 点击数字 / 字符串 行内编辑，Enter 应用
    树上 点击布尔 直接取反
    控制台 Enter 执行
    控制台 Esc 清空输入

    键盘输入的坑¶

    这个工具窗口是用 SDL 子窗口实现的，而在当前的 LÖVE 构建里，SDL 子窗口的键盘事件不可靠（即使窗口拿到了焦点也收不到按键）。因此引擎的做法是：

    • 主窗口 love.keypressed 里的按键会被 转发 给 DevTool.HandleKey ，由它统一处理字符输入与快捷键；
    • 只有当工具窗口 拿到了焦点 ，或者 鼠标正悬停在工具窗口上 时才会转发（由 DevTool.WantsKeys() 判定）；
    • 转发的同时，游戏场景照常收到这些按键 ，所以调工具和玩游戏不会互相抢输入。

    点进工具窗口时，它会尝试向系统申请键盘焦点 —— 这就是标题栏 KF:YES / KF:NO 指示的来源。如果焦点始终拿不到，只要 把鼠标移到工具窗口上 ，同样可以正常输入。
