    游戏逻辑与世界规则

    Game/Logics/ 是只有你这一个游戏才有的那部分：世界一开始长什么样、等级怎么涨、剧情开关叫什么、箱子里装了什么。改这里不需要动引擎。

    路径： Game/Logics/init.lua （世界的初始状态与规则表）、 Game/Logics/items.lua （物品表）。

    本页讲的是"世界规则"这一层。
    DATA 每个字段在运行时怎么用见 Overworld → 初始化与场景骨架 ；
    物品表怎么用也在这篇的 ITEMS 一节；
    Game 区的覆盖顺序见 Game 区与资源覆盖 。

    它是怎么被加载的¶

    -- Scripts/Libraries/Overworld/init.lua
DATA  = DATA or require("Game.Logics")
FLAG  = DATA.flags
CHEST = DATA.chests

    这个文件没有引擎兜底

    引擎是硬 require Game.Logics 的 —— 不像贴图、波次那样"Game 区没有就回退到 Scripts/ "。
    Game/Logics/init.lua 缺失就是整个主世界起不来。

    这张表就是存档

    存档页执行的是 Global.SetSaveVariable("Overworld", DATA) —— 整张 DATA 直接写盘。
    所以在 Logics 里加一个字段，等于给存档加一个字段。

    items.lua 是例外，它走 Game 优先： Game.Logics.items → Scripts.Logics.items （当前工程里引擎那份并不存在，实际只有 Game 区这份）。

    文件的骨架¶

    local path = (...):match("(.-)[^%.]+$")
local logic = {}

Global.SetVariable("FUN", math.random(0, 100))   -- ① 顶层就能设全局变量

logic = { ... }            -- ② 世界的默认状态（玩家、位置、背包…）
logic.flags   = { ... }    -- ③ 剧情开关
logic.chests  = { ... }    -- ④ 箱子里有什么
logic.lv_data = { ... }    -- ⑤ 世界规则：等级曲线

-- Global.DeleteSaveVariable("Overworld")          -- ⑥ 调试时强制开新档
if (Global.GetSaveVariable("Overworld")) then
    logic = Global.GetSaveVariable("Overworld")    -- ⑦ 存过档就用存档那份
end

return logic
    • ① 顶层可以直接设全局变量。 FUN 就是 UNDERTALE 里那个"有趣度"，每次开新档重新随机。
    • ⑦ 有存档就整份替换掉默认值 —— 所以改了 Logics 却没生效是它造成的，见 Overworld → 初始化与场景骨架 里的 DATA 一节。调试时把那句注释掉，或者用 ⑥ 直接删存档。

    lv_data：成长曲线¶

    这是最典型的一条"世界规律" —— 满级多少、每级多少血、多少经验升一级，全在这一张表里。

    字段 含义
    lv 等级
    hp 升到这一级时的最大血量（直接覆盖 maxhp ）
    at 攻击力 → 写进 DATA.player.atk
    df 防御力 → 写进 DATA.player.def
    totalExp 升到这一级所需的累计 EXP（不是"这一级要多少"）
    引擎自带的 20 级表

    升级是怎么结算的¶

    战斗结束时， Scripts/Scenes/Battle/scene_battle_ow.lua 的 ReturnData() 会把结果写回 DATA ：

    DATA.player.exp = DATA.player.exp + (Battle.EXP or 0)
DATA.player.gold = DATA.player.gold + (Battle.GOLD or 0)
DATA.player.hp = math.max(0, math.min(DATA.player.maxhp, Player.hp))

while (DATA.lv_data[DATA.player.lv + 1] and
       DATA.player.exp >= DATA.lv_data[DATA.player.lv + 1].totalExp) do
    local old_max = DATA.player.maxhp
    DATA.player.lv = DATA.player.lv + 1

    local row = DATA.lv_data[DATA.player.lv]
    DATA.player.maxhp = row.hp
    DATA.player.atk = row.at
    DATA.player.def = row.df

    -- UNDERTALE 的规则：最大血量涨多少，当前血量也跟着涨多少
    DATA.player.hp = math.min(DATA.player.maxhp, DATA.player.hp + (DATA.player.maxhp - old_max))
end

    结算规则小结

    • 一次战斗可以连升多级（是 while 不是 if ）。
    • maxhp / atk / def 是按表覆盖，不是累加；表里写多少就是多少。
    • 涨的那部分最大血量会同时加到当前血量上（升级即回血）。
    • weapon / armor / gold / exp 不归等级表管。

    watk / edef 目前只是显示用

    player.watk （武器攻击）与 player.edef （防具防御）只出现在 STAT 菜单的显示里，引擎没有把它们加到 atk / def 上。
    想让装备真的生效，得自己在结算或伤害计算处加上。

    想扩到 LV 30？直接加行就行¶

    封顶完全由表长决定 —— 循环条件是 DATA.lv_data[lv + 1] 存在，所以：

    { lv = 21, hp = 106, at = 50, df = 15, totalExp = 150000 },
{ lv = 22, hp = 113, at = 52, df = 15, totalExp = 220000 },
-- ... 一直加到 30

    加完不用改任何引擎代码，菜单、升级结算、经验显示会一起跟着走。

    满级时打开 STAT 菜单会崩

    Overworld.CalcNextEXP() 是这样写的：

    local next_total = DATA.lv_data[DATA.player.lv + 1].totalExp   -- 没有判空

    满级时 lv_data[lv + 1] 是 nil ，直接索引 nil 会报错 —— 表现是升到满级后一打开 STAT 页面就崩。
    两个办法：把等级表多写一行（比如满级是 20 就写到 21，让 totalExp 保持一个够大的值），或者自己给 CalcNextEXP 补个判空（返回 0 或 "--" ）。

    经验阈值别写反

    totalExp 是累计经验，不是"这一级需要多少"。第 20 级的 99999 意思是"总共攒够 99999 EXP 才能到 20 级"，不是"再打 99999"。

    flags：世界的开关¶

    logic.flags = {
    test_killed = 0
}

    引擎会把它挂成全局 FLAG ，直接用即可：

    FLAG["test_killed"] = 1
if (FLAG["test_killed"] == 1) then
    -- 剧情分支
end

    因为整张 DATA 都会进存档， flags 天然就是会存档的剧情开关，不需要额外操作。

    chests：箱子里有什么¶

    logic.chests = {
    chest = { "Spider" },   -- 键名对应箱子的 id
    chest1 = {}
}

    同样会挂成全局 CHEST 。开箱子时按 id 取这里的列表，取完记得清空，否则能反复开（详见 菜单 · 存档 · 箱子 ）。

    加字段时要想的两件事¶

    老存档没有新字段

    存档是按整张表存的。你给 player 加了 sanity = 100 之后，之前存的档里这个字段是 nil 。
    读的时候要么给默认值（ DATA.player.sanity or 100 ），要么开发期直接删存档重开。

    getcell 被引擎强制打开了

    player.getcell 在 Logics 里写的是 false ，但 Scripts/Libraries/Overworld/stat.lua 顶层有一句 DATA.player.getcell = true 会把它覆盖掉。
    结果是 CELL（电话）菜单默认就是开着的，改 Logics 不生效。

    为什么单独有这一层¶

    把"世界规律"收在一个文件里，好处是调数值不用碰引擎：

    想改什么 改哪儿
    满级是 20 还是 30 lv_data 加/删行
    每级多少血、多少攻防 lv_data 的 hp / at / df
    升级要多快 lv_data 的 totalExp
    开局叫什么、拿什么、在哪出生 player 与 room / marker / position
    剧情分支记在哪 flags
    箱子里给什么 chests
    物品有哪些 同目录的 items.lua

    也就是说，世界观层面的设定（这是个"20 级封顶的世界"还是"30 级的世界"）在 Game/Logics/ 里就能定完，引擎完全不用动。
