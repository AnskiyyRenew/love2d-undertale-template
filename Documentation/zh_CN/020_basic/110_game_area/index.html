    Game 区与资源覆盖

    Game/ 是每个游戏自己的内容根目录，也就是本文档中反复出现的 Game 区 。
    引擎自带的资源全部放在各自的原始目录里；你自己的内容则一律放进 Game 区。

    这样区分的目的只有一个：让引擎的更新不会冲掉你的游戏内容。

    两条路径的分工¶

    引擎目录 Game 区
    作用 引擎自带的默认内容 你这个游戏自己的内容
    更新引擎时 会被整体替换 原样保留
    优先级 低（兜底） 高（优先）

    因此开发时请遵守一条铁律：不要直接改引擎目录下的东西。

    如果你确实需要改动引擎自带的行为或资源，正确做法是把它复制一份到 Game 区，然后在 Game 区那份上改。引擎目录那份保持原样，将来升级引擎时直接覆盖即可，你的改动不会丢。

    总规则：Game 优先，主目录兜底¶

    除了少数只认 Game 区的内容，其余资源在查找时都遵循同一套顺序：

    1. 先看 Game 区有没有同名的。
    2. 有 → 直接用 Game 区这一份（覆盖生效）。
    3. 没有 → 回退到引擎目录那一份。

    这套顺序对路径生效，与文件类型无关：场景、贴图、音频、翻译、回合脚本、地图、攻击模式、灵魂、物品表都走这个逻辑。

    哪些内容支持覆盖¶

    内容 Game 区路径 引擎兜底路径
    场景 Game/Scenes/<name>.lua Scripts/Scenes/<name>.lua
    贴图 Game/Resources/Sprites/ Resources/Sprites/
    音效 Game/Resources/Sounds/ Resources/Sounds/
    音乐 Game/Resources/Music/ Resources/Music/
    字体 Game/Resources/Fonts/ Resources/Fonts/
    翻译（按键叠加） Game/Localization/ Localization/
    回合脚本 Game/Waves/<name>.lua Scripts/Waves/<name>.lua
    攻击模式 Game/Attacks/<name>.lua Scripts/Libraries/Battle/PlayerAttacks/<name>.lua
    灵魂 Game/Souls/<name>.lua Scripts/Libraries/Battle/Player/Souls/<name>.lua
    地图 Game/ 下同相对路径 Maps/
    物品表 Game/Logics/items.lua Scripts/Logics/items.lua

    两个容易踩的点

    • 字体写文件名就行： Fonts.New("determination_mono.ttf", 27) 会先查 Game/Resources/Fonts/ 。引擎里所有字体加载都已走这个入口，所以你不用改任何调用代码，放个同名文件进去就换掉了。
    • 物品表的引擎兜底目录 Scripts/Logics/ 目前并不存在（引擎自带没有这一份），所以物品表现在事实上只有 Game/Logics/items.lua 一个来源。同目录的 Game/Logics/init.lua 更是硬性 require，连回退都没有。

    哪些内容只认 Game 区¶

    下面这些内容没有可用的引擎侧同名目录，属于游戏独有数据，直接写在 Game 区即可，不需要考虑覆盖问题：

    内容 路径
    遭遇战 Game/Encounter/
    怪物动画 Game/Animations/
    游戏逻辑数据 Game/Logics/
    Hack 脚本 Game/Hacks/
    整模块替换映射 Game/Overrides.lua
    配置覆盖 Game/conf_pure.lua

    这也是为什么这几项在文档里只出现一个路径——它们本来就是你的，引擎不会提供默认版本。

    其中 Game/conf_pure.lua 是「叠加」而不是「兜底」，和其他几项都不一样：引擎总是先执行根目录的 conf_pure.lua 把所有默认值铺好，再执行你这份去覆盖同名的变量。所以你只需要写想改的那几行。万一你那份执行到一半报错，引擎会整体回滚到默认值，并打印一句 [Conf] WARNING: ... exists but failed to load; using the engine defaults ... ，游戏照样能起来。

    游戏逻辑里装的是什么

    世界规则（等级曲线、满级怎么扩、剧情开关、箱子内容）单独有一页： 游戏逻辑与世界规则 。

    Game/Logics 别和 Game/Hacks 搞混

    这两个目录都叫"逻辑"类的名字，但职责完全不同： Game/Logics/ 放的是数据（等级表、箱子内容）， Game/Hacks/ 放的是代码（改写引擎行为）。下一节讲后者。

    用 Hack 改写引擎内部¶

    上面所有办法都有一个共同前提：内容本身要"能放在别处"。可是有些东西不属于任何一类——比如战斗 UI 的排版、战斗流程的状态机、贴图库内部的行为。它们住在 Scripts/Libraries/ 里，以前想改就只能动引擎。

    Game 区给了两个受支持的入口：

    1. Game/Overrides.lua —— 声明式整模块替换¶

    一个 ["引擎模块名"] = "Game 模块名" 的映射表，适合"这个模块我整份重写"：

    -- Game/Overrides.lua
return {
    ["Scripts.Libraries.Battle.UI"] = "Game.UI.Battle",
}

    2. Game/Hacks/*.lua —— 命令式打补丁¶

    启动时按文件名数字前缀顺序各执行一次，适合"我只想改其中一两个函数"：

    -- Game/Hacks/010_my_battle.lua
return {
    name = "My battle tweak",
    apply = function(Hack)
        Hack.After("Scripts.Libraries.Battle", function(battle)
            -- 引擎加载完 Battle 之后跑一次
        end)
    end
}

    可用的原语有 Hack.Replace （整模块替换）、 Hack.After （加载后回调）、 Hack.Wrap （包住某个函数）、 Hack.Set 、以及更偏内部的 Hack.Patch 。完整说明与注意事项见 Game/Hacks/README.md 。

    文件名规则

    Game/Hacks/ 里每一个 .lua 都会被当成一个入口执行，只有以下划线 _ 开头的文件会被跳过。
    所以如果你想把一整个模块放在这个目录里当替换素材，文件名一定要带下划线（比如 _my_ui.lua ），否则它会被当成入口跑一遍，然后抱怨"这个文件既没返回函数也没返回 {apply = ...}"。

    改完按 F5

    两个入口都在热重载时先撤销、再重新应用，所以改完配置文件按 F5 就会生效，不用重启。

    覆盖坏了会发生什么¶

    这一点很重要，值得单独说：覆盖失败一定会报出来，不会静默。

    引擎在查找资源时会把「文件不存在」和「文件存在但加载时报错」严格区分开，于是有三种结果：

    三种结果

    1. 正常覆盖 —— Game 区有，且能正常加载。无输出，直接用 Game 区那份。

    2. 覆盖没找到，回退成功 —— Game 区没有，用的是引擎目录那份：

    [Battle] WARNING: 'bones.wave1' not found in Game.Waves. (fell back to Scripts.Waves.bones.wave1).

    这种情况是正常的，你只要确认「我确实没写这个覆盖」即可。

    3. 覆盖存在但坏了 —— Game 区有这份文件，但它一加载就报错：

    [Battle] WARNING: 'Game.Waves.bones.wave1' exists but failed to load; using Scripts.Waves.bones.wave1 instead.
[Battle]   <真正的错误信息>

    看到 exists but failed to load 就说明你的覆盖没生效，同时真正的报错也被打印出来了，照着修即可。

    不同子系统的警告前缀不一样，认准 exists but failed to load 这几个字就行：

    前缀 出自
    [Battle] 遭遇、波次、攻击模式、灵魂
    [Scenes] 场景
    [Overworld] 地图、物品表
    [Conf] Game/conf_pure.lua
    [Hack] Game/Hacks/ 与 Game/Overrides.lua

    为什么不能把「找不到」和「坏了」混为一谈

    早期版本的实现是用 pcall(require, ...) 的成败来判断模块在不在的。
    问题是 pcall 返回 false 有两种完全不同的原因：文件不存在，和文件存在但顶层代码报错。
    把后者当成「不存在」，会导致两件坏事同时发生：回退链条被静默截断（你以为覆盖生效了，其实跑的是旧版），以及真正的错误被吞掉不显示。
    所以现在是先查文件是否存在，再决定要不要 require 。多写几行，换来的是一旦出问题你一定能看见。

    一些注意事项¶

    • 路径一律用正斜杠 / ，从项目根目录开始写。
    • 文件名必须完全一致，覆盖是「同名替换」而不是「就近合并」。Game 区放了 px.png ，引擎目录的 px.png 就整体不再被使用。
    • 地图的图片引用是相对路径。引擎的地图 .lua 里用 ../images/... 引用图块，所以覆盖地图时，Game 区那份也要自带对应的 ../images/ 目录树，否则会出现图块丢失。
    • 覆盖没生效时，先看终端。 上面第三种情况一定会打警告，不要凭感觉猜。
