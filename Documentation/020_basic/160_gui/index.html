    ❕️ GUI Library

    The engine's built-in UNDERTALE-style graphical interface library, providing components such as windows, text, buttons, sliders, text inputs, and dropdowns, plus an input helper that maps mouse coordinates from window space to canvas space.

    Library path: Scripts/Libraries/GUI/ (folder form, init.lua is the entry).

    Loading: in main.lua do GUI = ImportFile("GUI"), must be after Typers (Label wraps Typers.InstText). After loading, you can call the global GUI directly from any scene.

    Dependencies:

    • Typers — text in Label / Button / Slider / TextInput / Dropdown all goes through Typers.InstText, auto-routing Chinese/English.
    • Layer System — all drawing is registered via Layers.add_external, no sprites created.

    Coordinates and Layer Conventions¶

    Convention Description
    Coordinate semantics Top-left (x, y) + width/height (w, h); Window:SetCenter switches to center-point semantics (compatible with battle-box semantics).
    Default layer 1000 (above battle elements); adjustable via :SetLayer, or pass layer at New.
    Mouse coordinates love's mouse coordinates are in window screen space; GUI is in 640×480 canvas space. The two are converted via GUI.Input.ScreenToCanvas (see below).
    Pixel snapping internal math.floor(v + 0.5) snapping, consistent with Sprites.snapCoord.
    Color restore restores white after each draw, so color does not leak to other layers in the same frame (pitfall #7).

    Font Conventions¶

    Through testing, only the following font sizes render clearly. The GUI library reuses Typers.InstText's bondfont mechanism directly, so the caller does not need to handle fonts:

    Language Font Size
    English Resources/Fonts/determination_mono.ttf 27 or 13
    Chinese Resources/Fonts/simsun.ttc only 13; for size 27 use scale=2 to enlarge

    Mixed Chinese/English layout is auto-routed by Typers.InstText per character byte (charlen judges 1=English / >1=Chinese); GUI.Label is a thin wrapper over it.

    Lifecycle¶

    The caller holds the component reference and calls :Destroy() on each one in scene.clear. Layers.clear() stops external drawing but does not release Label's InstText text-cache reference (InstText uses reference counting), so you must call Destroy explicitly, otherwise it leaks and may trigger "Cannot use object after it has been released".

    TextInput.Focus opens system text input (love.keyboard.setTextInput); Blur / Destroy must close it, otherwise it still receives input after leaving the scene.

    Mouse Input Helper GUI.Input¶

    Key point: love's mouse coordinates are in window screen space, while GUI components are in canvas space — they must be converted to hit-test.

    GUI.Input uses the globals DrawX / DrawY / ScreenScale (set by updateScreenScale in main.lua) for conversion, and does button edge detection, so the scene can poll IsPressed / IsReleased / IsDown every frame — semantics match the keyboard's hand-written prev table.

    State model:

    • held is real-time — OnPressed / OnReleased change it directly, IsDown reflects the current state.
    • pressed / released / wheel are frozen per frame — async events first go into pending, then at the start of Update() are swapped into state and pending is cleared, so IsPressed / IsReleased are true exactly on the next frame.

    Scene wiring (main.lua already forwards all mouse callbacks to the scene, when not pausing):

    -- the four love callbacks forwarded to the helper
function scene.mousepressed(x, y, button)  GUI.Input.OnPressed(x, y, button) end
function scene.mousereleased(x, y, button) GUI.Input.OnReleased(x, y, button) end
function scene.mousemoved(x, y)            GUI.Input.OnMoved(x, y) end
function scene.wheelmoved(x, y)            GUI.Input.OnWheel(x, y) end

function scene.update(dt)
    GUI.Input.Update()   -- must be at the very start of scene.update, freezes this frame's state

    local mx, my = GUI.Input.GetCanvasMouse()   -- canvas-space coordinates
    if (GUI.Input.IsPressed(1)) then            -- left button = 1; just pressed this frame
        -- hit-test / trigger component
    end
    local wheel = GUI.Input.GetWheel()          -- +1 up / -1 down / 0
end
    GUI.Input interface overview
    • ScreenToCanvas(sx, sy) pure conversion: (sx-DrawX)/ScreenScale, (sy-DrawY)/ScreenScale.
    • GetCanvasMouse() current canvas-space cursor position.
    • IsDown(button) whether held (real-time).
    • IsPressed(button) whether just pressed this frame (edge).
    • IsReleased(button) whether just released this frame (edge).
    • GetWheel() this frame's wheel delta (+1 / -1 / 0).
    • OnPressed(sx, sy, btn) / OnReleased(...) / OnMoved(sx, sy) / OnWheel(x, y) called in the love callbacks.
    • Update() called at the start of scene.update.
    • Reset() called in scene.clear — prevents the mouse from being held when switching scenes, where love may not deliver mousereleased to the new scene, causing IsDown to lock up.

    Components¶

    Window¶

    Visual window: two stacked rectangles (thick outer border + inner fill), purely visual — no collision, no player constraint. Animation uses the same "rate-limited approach to target" as the battle box (smooth_value).

    local win = GUI.Window.New{
    x = 200, y = 100, w = 240, h = 120,
    thickness = 5, layer = 1000,
}
win:ResizeWithSpeed(300, 150, 15, 15)   -- smooth resize (must call win:Update(dt) in scene.update)
win:SetCenter(320, 240)                 -- switch to center-point semantics
win:SetVisible(false)
-- scene.clear: win:Destroy()
    Window interface
    • New{x, y, w, h, thickness, outer, inner, layer, visible} outer color defaults to MainColor, inner defaults to black.
    • :MoveTo(x, y, imm) / :SetCenter(cx, cy, imm) move; imm=true syncs immediately without animation.
    • :Resize(w, h, imm) / :ResizeWithSpeed(w, h, sw, sh) resize.
    • :SetThickness(t, imm) border thickness.
    • :SetOuterColor(c) / :SetInnerColor(c) / :SetOuterAlpha(a) / :SetInnerAlpha(a).
    • :SetVisible(v) / :SetLayer(layer).
    • :Update(dt) smooth-animation driver (static menus can skip).
    • :GetCenter() / :ContainsPoint(x, y) center point / hit-test.
    • :Destroy() idempotent.

    Label¶

    Text label, thin wrapper over Typers.InstText, auto-routing mixed Chinese/English.

    local lbl = GUI.Label.New("Hello 世界", {320, 200})
lbl:SetAlign("center")
lbl:SetText("new text")
lbl:SetColor(1, 1, 0)     -- yellow
lbl:SetAlpha(0.5)
lbl:SetWrapWidth(200)     -- auto-wrap (pass nil/0 to disable)
-- scene.clear: lbl:Destroy()
    Label interface
    • New(text, pos, layer, size) pos={x,y}; size={boxWidth,_} enables auto-wrap.
    • :SetText(t) / :SetAlign(mode) ("left" / "center" / "right") / :SetColor(r,g,b) / :SetAlpha(a).
    • :SetPosition(x, y) / :SetWrapWidth(w) (auto Rebuild after width change) / :Rebuild().
    • :Inst() get the underlying InstText directly (advanced use, use with care).

    Changing auto_wrap / size does not auto-reflow

    After changing InstText's auto_wrap and size you must call :Rebuild(), otherwise lines won't reflow. Label.SetWrapWidth already calls it internally; if you change inst.auto_wrap directly you must Rebuild manually.

    Button¶

    Button, UNDERTALE-style selected state. Keyboard-selected = prefix "> " + yellow; mouse-hover = yellow without prefix (the two states are visually distinct); unselected uses 2-space monospace padding to prevent text jitter.

    local btn = GUI.Button.New{
    x = 200, y = 150, text = "FIGHT",
    w = 200, h = 30,            -- mouse hit area
    onSelect = function() end,
}
btn:SetSelected(true)          -- keyboard-selected
btn:SetHovered(true)            -- mouse-hover
if (confirm) then btn:Trigger() end
    Button interface
    • New{x, y, w, h, text, selected, onSelect, layer, prefix, pad, colorNormal, colorSelected}.
    • :SetSelected(v) / :SetHovered(v) / :SetText(t) / :SetPosition(x, y) / :SetOnSelect(fn).
    • :ContainsPoint(x, y) hit-test.
    • :Trigger() trigger the onSelect callback.
    • Color logic: selected or hovered → colorSelected (yellow), otherwise colorNormal (white).

    Slider¶

    Horizontal slider: track + knob, two rectangles. Pure component that does not read input; the scene drives it via :Move / :SetValue / :DragTo / :Wheel.

    local s = GUI.Slider.New{
    x = 200, y = 300, w = 240,
    min = 0, max = 100, value = 50, step = 1,
    focused = true,             -- knob turns yellow
}
-- keyboard: :Move(1) / :Move(-1)
-- mouse: :DragTo(mx, my) drag / :Wheel(dir) wheel / :ContainsPoint hit-test
local v = s:GetValue()
    Slider interface
    • New{x, y, w, min, max, value, step, trackH, knobSize, trackColor, knobColor, focusedColor, focused, showLabel, layer}.
    • :Move(dir) +1 / -1 step; :SetValue(v) / :SetRange(min, max) / :GetValue().
    • :DragTo(cx, cy) canvas-space x → value (call while dragging).
    • :Wheel(dir) wheel (same as :Move).
    • :SetFocused(v) knob highlight.
    • :ContainsPoint(x, y) hit-test (with 4px margin).
    • step grid-snapping prevents float drift from continuous Move.

    TextInput¶

    Single-line text input box: window-style thin border + text + blinking cursor. Focus opens system text input (love.keyboard.setTextInput) so the OS emits character events; the scene routes textinput / keypressed into it.

    local ti = GUI.TextInput.New{
    x = 200, y = 100, w = 240, h = 32,
    placeholder = "Name", maxLen = 16,
    onSubmit = function(self) print(self:GetText()) end,
}
-- scene routing:
--   scene.textinput(t)  -> ti:HandleTextInput(t)
--   scene.keypressed(k) -> ti:HandleKeyPressed(k)
--   scene.update(dt)    -> ti:Update(dt)        -- cursor blink
-- click to focus: if (ti:ContainsPoint(mx,my)) then ti:Focus() else ti:Blur() end
    TextInput interface
    • New{x, y, w, h, thickness, placeholder, maxLen, layer, onSubmit}.
    • :Focus() / :Blur() / :SetFocused(v) — toggle system text input + setKeyRepeat (backspace long-press repeat).
    • :HandleTextInput(text) append character (filters newlines, truncates by maxLen).
    • :HandleKeyPressed(key) returns whether consumed: backspace deletes one UTF-8 codepoint, escape blurs, return / kpenter triggers onSubmit; other keys return false (not consumed, keyboard navigation works as usual).
    • :SetText(t) / :GetText() / :ContainsPoint(x, y) / :Update(dt) / :SetPosition(x, y).

    maxLen counts characters, not bytes

    maxLen counts UTF-8 codepoints, so one CJK character counts as 1. Backspace also deletes one codepoint (not one byte).

    Dropdown¶

    Dropdown box: a trigger button shows the current selection; clicking expands the option list. w is the menu width, buttonW (optional, defaults to w) is the trigger button width. expand="up"|"down" specifies the expand direction.

    local dd = GUI.Dropdown.New{
    x = 200, y = 200, w = 180,
    buttonW = 180,            -- optional, default = w
    buttonH = 24, itemH = 24,
    items = {"Red", "Green", "Blue"},
    selected = 1,
    expand = "down",          -- "up" | "down"
    layer = 1001,
    onSelect = function(self, idx, text) print(idx, text) end,
}
-- scene routing (scene.update, after GUI.Input.Update()):
local mx, my = GUI.Input.GetCanvasMouse()
dd:SetHover(mx, my)
if (GUI.Input.IsPressed(1)) then
    local consumed = dd:HandleClick(mx, my)  -- click trigger button = expand/collapse; click option = select+collapse; click outside = collapse but not consumed
end
    Dropdown interface
    • New{x, y, w, buttonW, buttonH, itemH, thickness, gap, expand, items, selected, layer, onSelect}.
    • :SetHover(mx, my) call every frame, updates hover highlight.
    • :HandleClick(mx, my) call on click, returns whether consumed.
    • :SetExpanded(v) / :IsExpanded() / :GetSelected() / :GetSelectedText() / :SetItems(items) / :SetPosition(x, y) / :SetOnSelect(fn) / :ContainsAny(mx, my).
    • Selected item = yellow + prefix "> "; hovered item = yellow without prefix; others = white (consistent with Button).
    • Trigger button border turns yellow on hover / expand; menu border stays white.
    • Menu is left-aligned to the trigger button; option row positions fixed at New, expanding only toggles alpha=0/1.

    Pitfalls¶

    Same-layer occlusion: background cannot share a layer with text

    Layers within the same layer are ordered by _id (registration order); later registration draws later (visually on top). If a component's background (the black inner layer of drawWindow) and a text Label share a layer, and the background is registered later, the black fill will cover the text.

    Fix: inside the component put the background on layer and the text on layer+1 (cursor on layer+2). TextInput and Dropdown both do this.

    Closure-referenced local must be declared first

    If a component's onSubmit / onSelect callback closure references a local variable (e.g. feedback_timer), and that local is declared after the closure, the closure will write to the global instead of that local (Lua does not hoist locals).

    -- wrong: the onSubmit closure writes the global feedback_timer, not the local below
local ti = GUI.TextInput.New{ onSubmit = function() feedback_timer = 120 end }
local feedback_timer = 0

-- right: local declared before the closure
local feedback_timer = 0
local ti = GUI.TextInput.New{ onSubmit = function() feedback_timer = 120 end }

    luac -p won't catch this (it's a runtime scope issue, not a syntax error).
