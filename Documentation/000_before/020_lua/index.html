    This page is not really suited for beginners—it's more like a reference manual to consult as development progresses.
    Several other pages will later hyperlink back to this one.

    Variables¶

    This is the thing you'll interact with most during development.
    Simply put, the vast majority of files with the .lua extension contain variables internally.

    Variable Examples

    a = 10          -- single letter
abb = ""        -- multiple letters
_count = 0      -- starts with underscore
playerHP = 20   -- camelCase

    All of the above are variables.

    Naming Conventions (must follow)¶

    1. Variables may not be named with keywords (such as if, end, etc.)
    2. Variables may not be named starting with a number (such as 1var, etc.)
    3. The engine uniformly uses ASCII (English letters, numbers, underscores) for naming.

    Can Chinese actually be used as variable names?¶

    Yes, but strongly not recommended.

    SoulEngine runs on LuaJIT (bundled with LÖVE 12), and LuaJIT's lexer treats bytes above 0x80 as valid identifier characters, so the following actually runs in the game:

    你好 = ""
你好 = "hello"
print(你好)          -- hello

function 打招呼() return "hi" end
print(打招呼())      -- hi

local t = {名字 = "Chara"}
print(t.名字)        -- Chara

    Switch Lua interpreters and it explodes

    Standard Lua 5.1 (PUC) will outright reject the above syntax:

    lua.exe: t.lua:1: unexpected symbol near 'ä'

    Yet the verify_*.lua validation scripts in the engine repo, and parts of the build/export process, use standard Lua. One source, two runners—the half with Chinese identifiers will suddenly throw a syntax error on the other path, and the error location points to bytes rather than the characters you wrote.

    So just write ASCII uniformly

    Chinese isn't unusable—it's just that you should only put it in strings (as well as in places like Tiled layer names and comments that are "for humans and other tools to read"):

    local greeting = "你好"      -- ✅ write freely inside strings
local name = "Chara"          -- ✅ variable names use ASCII

    All variables, functions, and table fields inside the engine are ASCII—following along will cause no problems.

    Common Types¶

    1. Numbers: 1, 2, 3
    2. Strings (also called text): "hello", "I am a complete sentence.", "rolling log"
    3. Tables, the most powerful variable (can be treated as both an array or a dictionary at the same time): {1, 2, 3, 4}
    4. Booleans (imagine a switch): true, false
    5. Functions (not mathematical! Used by adding parentheses at the end): cool()

    Keywords¶

    Variables also have their hierarchy. Although not strictly defined, if you type a special word, that word may get a highlighting effect, indicating it is a keyword.

    Let's look at some simple examples and comparisons:

    Keywords and non-keywords

    if then while for do end elseif else in

    IF aaa time var1 incredible

    Note: I didn't force the color change—it's caused by keyword highlighting being recognized.
    Here is a mixed version:

    Keyword Highlighting

    if time == a then
end

    Summary: avoid these keywords when naming.

    Common Combinations¶

    Here, we won't cover overly complex code blocks—only the most commonly used ones:

    1. Conditional: if a value meets a condition, perform an operation.

    if statement

    if time == 60 then
    a = a + 1
end

    The above executes: when time equals 60, it runs the content wrapped by if - end. (Here, for example, a increases by 1.)

    1. if-chain: continuously matches each condition to determine the final matching branch:

    if chain

    if     time == 60 then
                         branch one
elseif time == 90 then
                         branch two
elseif time == 95 then
                         branch three
else
                         final branch
end

    The above executes: when time equals 60, 90, 95, it enters branches one, two, three respectively.
    If none match, it enters the final branch managed by else.

    1. Loop: use an abstract number to repeatedly perform an operation:

    normal for loop

    for i = 1, 10, 1
do
    a = a + 1
end

    The above executes: create a new i variable, starting from 1 and increasing by 1 each time until 10.
    During this period, each time it adds 1, it runs the content wrapped by for - end once.

    Simply put, it runs ten times.

    An even more powerful loop:

    while loop

    while i < 10
do
    i = i + 1
end

    The above executes: detects that i is less than 10, and continuously runs the i = i + 1 operation, until i no longer meets the condition.

    Short-circuit Selection¶

    Basic Semantics of or¶

    If a exists or is true, then choose a; otherwise choose b.
    Through this method, we can create a default-value substitution effect.

    The format is as follows: 

    var = a or b

    Example

    If test is not given an argument, it will default to the content after or, which in this example is default output.. 

    local function test(b)
    print(b or "default output.")
end
test()

    and or Conditional¶

    If condition a is true, use b; otherwise use c.
    Through this method, we can complete binary or multi-way selection in a single line.

    The format is as follows: 

    var = a and b or c

    This operation relies heavily on logic and parenthesis handling.

    Commonly seen when setting the battle box's minimum size to 16:

    Example

    If width is greater than 16, use width; otherwise use 16.

    local _width = (width > 16) and width or 16

    Nested Operation

    Each layer is a checkpoint—among the three variables cfg, cfg.db, and cfg.db.host, if any one does not meet the standard, it will force the output localhost.

    local config = {
    db = { host = "127.0.0.1" }
}

local function getHost(cfg)
    return (cfg and cfg.db and cfg.db.host) or "localhost"
end

print(getHost(config))                        -- 127.0.0.1
print(getHost({ db = {} }))                   -- localhost
print(getHost(nil))                           -- localhost
