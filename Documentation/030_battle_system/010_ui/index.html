    UI

    Main body init.lua, state hub stateinner.lua, button system buttons.lua

    Main Body init¶

    This file is responsible for drawing the contents under the battle box and managing the state hub.
    In the battle scene, it appears as the global variable UI.

    Below are the available methods:

    UI Methods

    • UI.SetBarMaxLength(length) Set the maximum length of the HP bar (in pixels).
    • UI.SetHPBarColor(color) Set the color of the HP bar.
    • UI.SetMaxHPBarColor(color) Set the color of the HP bar's background trough (i.e. the full-background bar behind the HP bar).
    • UI.ToggleKR(bool) Whether to enable KR. No animation; write your own if needed.
    • UI.GetKRStarted() Get whether KR has already been enabled.
    • UI.newBounceText(text, pos, color) Used in the attack animation; after the attack animation finishes playing, it generates a damage-number text (or MISS text). See Attack Resolution for details.
      • text The text to print. Cannot be Chinese.
      • pos Where the bounce starts.
      • color The color of the bouncing text. Default red {1, 0, 0}.
    • UI.newMissText(text, pos, color) Generates new static text, commonly seen when the player is at the calibration screen but misses the attack by not pressing the attack key.
      • text The text to print. Cannot be Chinese.
      • pos Where the bounce starts.
      • color The text color. Default white {1, 1, 1}, with a built-in black outline.
    • UI.newMonsterBar(pos, start, target) Generates a tweened monster HP bar on the enemy (used during attack resolution).
      • pos The enemy's position; the bar is drawn at its lower-left.
      • start The starting fill ratio (1 is full).
      • target The target fill ratio, which tweens from start to target over 30 frames.
    • UI.SetTextPosition(x, y) Modify the coordinates of the whole line of text starting with the name.
    • UI.GetTextPosition() Return the coordinates of the whole line of text starting with the name.
    • UI.MoveTextPosition(dx, dy) Move the text at a speed of (dx, dy).
    • UI.SetBarPosition(x, y) Modify the coordinates of the HP bar.
    • UI.GetBarPosition() Return the coordinates of the HP bar.
    • UI.MoveBarPosition(dx, dy) Move the HP bar at a speed of (dx, dy).
    • UI.MovePosition(dx, dy) Execute both the Text and Bar move functions at once.
    • UI.SetHPNameLimit(x) Modify the minimum x-coordinate of the HP label to x. Default is 245.
    • UI.GetLayout() Get the entire layout. If you want to systematically modify the layout, this function is recommended.
    • UI.GetHPBar() Return the HP bar representing the current HP.
    • UI.GetMaxHPBar() Return the HP bar representing the maximum HP.
    • UI.GetKRBar() Return the HP bar representing KR.
    • UI.GetBars() Return the three HP bars above.

    The state hub and UI are called within the main body, appearing respectively via these variables:

    UI.state & UI.buttons

    Buttons¶

    Responsible only for the logic of the four buttons: Fight, Act, Item, and Mercy.
    Below are the button methods; when calling them you need to write UI.buttons.xxx():

    Button Methods

    • buttons.GetButtons() Get the four buttons (in order).
    • buttons.ResetButtons() Return all buttons to their idle state.
    • buttons.ResetAllState() Return all buttons to their idle state and place the player at the first button.
    • buttons.RemoveButton(id) Remove the id-th button; this button will give no response.
    • buttons.SetLogic(logic) The button switching logic table; its contents are start, end, operation.
    • buttons.SetSprites(sprs) Set the four buttons' images at once; explained in detail below.
    • buttons.SetAnimations(anims) Set the four buttons' images at once; explained in detail below.

    Switching Images¶

    This is the original button table, laid out in order by button. The first item in each table is the idle image, and the second is the selected image.

    sprites = {
    {
        "UI/Battle Screen/spr_fightbt_0.png",
        "UI/Battle Screen/spr_fightbt_1.png"
    },
    {
        "UI/Battle Screen/spr_actbt_center_0.png",
        "UI/Battle Screen/spr_actbt_center_1.png"
    },
    {
        "UI/Battle Screen/spr_itembt_0.png",
        "UI/Battle Screen/spr_itembt_1.png"
    },
    {
        "UI/Battle Screen/spr_sparebt_0.png",
        "UI/Battle Screen/spr_sparebt_1.png"
    }
}

    Switching Animation¶

    Unlike images, this time we use multiple groups of data, i.e. adding one more layer on top of the table above:

    buttons.animations = (anims or {
    idle = {
        {{
            "poseur.png",
            "bullet.png"
        }, 0.1}
    },
    selecting = {
        {{
            "heart.png",
            "Overworld/spr_exc.png"
        }, 0.1}
    }
})

    Since what is actually being called is the sprite's SetAnimation operation, you need to pass two values: one is the image group and one is the interval.

    State Hub¶

    Preliminary Note

    Normally this file does not need to be modified, because the underlying supported logic is stable and unchanging. After understanding the state flow, you may move on to the next page.

    State Flow¶

    The battle system has the following states to determine which UI phase the player is in:

    • ACTIONSELECT The initial state of the player's turn (selecting buttons left/right).
    • FIGHTMENU The first page of the Fight button.
    • ACTMENU The first page of the Act button.
    • ITEMMENU The first page of the Item button.
    • MERCYMENU The first page of the Mercy button.
    • ATTACKING The second page of the Fight button; after selecting FIGHTMENU, pressing confirm again enters the attack calibration screen.
    • ACTIONMENU The second page of the Act button; after selecting ACTMENU, confirm to choose an action.
    • DEFENDING The enemy's turn.
    • DIALOGUERESULT After selecting an Act or Item, the state enters here to wait for narration text. Note the spelling is DIALOGUE, not DIALOG.
    • TRYINGFLEE Executed the instant Flee is pressed.
    • FLEEING Executed continuously after a successful Flee press, until the battle ends; can also be pulled back to the DEFENDING state by other means.
    • WIN Battle won. Plays victory text, hides the Soul, and after the text finishes, fades out and switches to the result scene.
