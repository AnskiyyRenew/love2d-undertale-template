# Update Log

> Changes since tag `v3.0.1-stable` (`56b162d`) — to be used as the release note for the next build.

## New Features
- Added stencil (mask) and shader support to all four typer modules, sharing one implementation in `Scripts/Libraries/Typers/render.lua`: `typer:SetStencils({mask})`, `typer:SetShaders({shader})`, `GetStencils` / `GetShaders`, `ClearStencils` / `ClearShaders` and `AddShader` / `RemoveShader` — the same calls a sprite takes. Both are optional and cost nothing while unset: the draw path behaves exactly as before until something is applied
- The typer shader pass bakes the text block into an offscreen canvas sized to its bounding box before running the chain. Every glyph is drawn from a font atlas, so a shader reading `tex_coords` would otherwise see atlas-relative UVs instead of 0..1 across the glyph (`WaveDistort` mapped them through `tex_size` and `Gradiant` lerped across the axis — both sampled the wrong texels). Shaders written for sprites now behave identically on text, glyphs keep their exact positions, and masks stack on top: the shader runs first, then the baked canvas is blitted through the mask. Canvases are cached and rounded up to 32px steps (up to 12 sizes), so text that grows while typing reuses one surface instead of allocating per frame
- Added an `immediate` argument to `timers.runFrame(func, interval, count, immediate)` and `timers.runSecond(...)`: when true, `func` fires once at creation and counts toward `count`, before the normal interval takes over — `runFrame(func, 60, 3, true)` fires immediately, then on frame 60 and frame 120
- Added `Scripts/Scenes/TEST/scene_typerfx.lua`, a visual check for the typer mask / shader support: a baseline block, mask-only, shader-only, both combined, and an animated `Wave` shader over an `EText`. Enable it by pointing `FirstRoom` at `TEST.scene_typerfx`
- Added `Scripts/Shaders/RGBOffset.glsl`, an RGB split shader that samples each channel from the same texture at its own offset and nothing else — no timer, no distortion, no tint. `r_offset` / `g_offset` / `b_offset` are independent `vec2` pairs, and `tex_size` converts them into UV so offsets are written in pixels: `{2, 0}` moves that channel two pixels right, `-y` moves it up, and `{0, 0}` leaves it in place. Sending `{1, 1}` as `tex_size` reads the same numbers as raw UV instead (0..1 across the whole texture), and leaving any uniform unset is harmless — the size falls back to 1 and the offsets to 0, which draws the texture unaltered. Two details keep the result predictable: a sample that lands outside the texture counts as empty rather than repeating the edge pixel, so no channel streaks outward along the sprite border, and alpha is the union of the three samples, so the split widens the silhouette to cover all three channels instead of clipping the two that moved. It loads like every other shader — `ImportFile("RGBOffset", "shader")` then `sprite:SetShaders({shader})`, or `typer:SetShaders({shader})` for text — and since each call returns a fresh object with its own uniforms, anything needing different offsets needs its own instance

- Added a host-channel option to the ShaderToy converter: `shadertoy.convert(code, { hostChannel = 0 })` (numeric shorthand `convert(code, 0)`) rewrites every `texture(iChannel0, uv)` into a read of the sprite's main texture, `Texel(texture, vec2((uv).x, 1.0 - (uv).y))`. This closes the gap where a converted shader is attached with `bg:SetShaders({s.shader})` but its `iChannel0` is meant to be the sprite's own image — the host image only ever reaches `effect` as the main texture, so there was nothing to pass to `setChannel`. The UV expression is preserved in full (nested calls and offsets included) and the y flip compensates for `fragCoord` pointing up while LÖVE's `texture_coords` points down; `hostFlipY = false` disables the flip and `hostChannels = {0, 1}` binds several channels. Host channels own no texture slot: no noise placeholder, no per-frame `send`, `setChannel` / `setAudioChannel` ignore them with a warning, and the unused `extern Image iChannelN;` declaration is dropped when nothing else references the channel. With no option the converted GLSL is byte-for-byte identical to before, so existing shaders and the multi-pass project are unaffected

- Added `Scripts/Scenes/TEST/scene_shader_host.lua`, a minimal visual check for the host-channel rewrite: a converted Shadertoy shader samples `iChannel0` on a white `px.png` and outputs its red channel, so a solid red screen confirms the channel reads the host texture rather than an external image. Enable it by pointing `FirstRoom` at `TEST.scene_shader_host`

- Added `Scripts/Libraries/Engine/DevMode.lua`, an in-game developer mode built around a **wave picker**, so a late turn can be tested without playing every earlier one. Typing `e` `n` `d` in sequence (1.5 s between keys, no modifier held, ignored while a text field has focus) unlocks it and opens the panel when a battle is loaded; the sequence again locks it, and `F10` toggles the panel. The list is the real directory tree of `Game/Waves/` and `Scripts/Waves/` — a folder is a namespace, so `Game/Waves/bones/wave1.lua` appears as `bones.wave1` and clicking it is exactly the string an encounter's `wave` field takes; no registry or numbering to maintain. Each row is clickable, folders expand / collapse, the list scrolls with the wheel, and the same actions are on the keyboard (`↑` `↓` `PageUp` `PageDown` `Home` `End`, `←` `→` for folders, `Enter` / `Space` to jump, `Esc` to close). While the panel is open the scene is paused through `scene.pausing`, so the running wave cannot hurt the player during browsing. `S` ends the current enemy turn, `I` toggles invincible (`Player.Hurt` returns at the entry point, so a lethal hit is never applied in the first place). Drawn into the 640x480 canvas with the engine's own 13 px font pair, so it scales and lines up with the rest of the game. Not loaded at all when `_RELEASED = true`

- Every player-facing string in `Scripts/Libraries/Engine/DevMode.lua` now goes through `Localize.localizeText` under `DevMode.*` keys added to the engine's `Localization/en.json` and `Localization/zh_CN.json` — the engine-side files, not a new Game-side copy: panel title, the two wave-root labels, the turn-script line, the live `wave:` / `state:` / `INVINCIBLE` header, the footer key hints, and every notice (jump failure, not in a battle, missing debug entry point, turn end, invincible on/off). A game can still override any single key from `Game/Localization/<lang>.json` without copying the whole layer. Lookups resolve the `Localize` global at call time because `main.lua` imports DevMode before Localize, so an F2 language reload is visible on the next draw; with no localizer available the key itself is shown instead of breaking the overlay. The Lua file is pure ASCII now

- Added `Battle.DebugJumpWave(wave_name)` and `Battle.DebugEndWave()` to `Scripts/Libraries/Battle/init.lua` (both no-ops returning `false` in a release build). A jump goes through the same transitions the normal flow uses instead of writing to `Battle._wave`: leaving DEFENDING runs `EndWave()` on the running wave (its bullets and objects are destroyed), drops that module from the require cache and restores the arena; then `clearWaveModule(target)`, `Battle.wave = target` and `ChangeState("DEFENDING")`, which re-runs the target file's top-level code. Two details keep a jump clean: the target module is always dropped from the cache, so the wave that is already playing re-runs its top-level code rather than replaying a stale closure, and `ENDED` on the shared `Battle.Waves` table is reset, since `ENDED = true` left over would end the next wave the moment it starts. Jumping from `ATTACKING` or a menu goes through ACTIONSELECT first; the attack pattern's own typer is not aborted, and the next entry into `ATTACKING` restarts it

## Bug Fixes
- Fixed the wave picker reporting "not in a battle" in a project whose `Battle` predates the debug entry points. `battleReady` counted `Battle.DebugJumpWave` being a function as part of its "is a battle running" test, so a battle scene sitting on an older `Battle/init.lua` — a game that copied `DevMode.lua` but not the `Battle` change — read as no battle at all, and every jump answered 当前不在战斗中 while the log line said `no battle loaded`. The state test now only answers the state question (encounter loaded, plus either a `battle` scene name or a `Battle.TIME_F` that advanced this frame), and the missing entry point is checked separately right before it is called, reporting `此项目的 Battle 缺少 DebugJumpWave，需同步 Battle/init.lua`. `DebugEndWave` behind `S` gets the same treatment
- Fixed the battle turn never receiving `dt`: `ui.Update(dt)` called `state.Update()` without forwarding the delta, so the delta was `nil` inside `state.Update` and stayed `nil` for everything downstream — `Battle._wave.Update(dt)` (DEFENDING), `Battle.attack.Update(dt)` (ATTACKING) and `Battle.FleeUpdate(dt)` (FLEEING). Any wave code that actually reads `dt` — a shader's `update(dt)`, a timer, or movement integration — silently ran on `nil`, which is what surfaced as an error when a converted Shadertoy shader was driven from a wave's `Update`. The delta is now forwarded from `ui.Update` into `state.Update`, so `dt` is the real frame time again in all three states. This was a long-standing bug rather than a regression: it went unnoticed because most wave code does not read `dt` at all

- Removed the only Lua 5.2+ syntax from the engine: `Scripts/Libraries/Tween.lua` used four `goto continue` jumps and a `::continue::` label in `Tween.Update`, which made `Packager/check_compat.py --strict 3` (love.js / Lua 5.1 semantics) report six blocking errors for the template itself, even though LuaJIT on Windows and Android accepted them. `Update` now dispatches the same cases through `if` / `elseif` / `else` branches — delay countdown, finishing (write the final value, then remove), unknown easing, and a failing `variableSetter` — with unchanged ordering, removal points and `time` increments, so waves, typers and bone walls keep their exact frame sequences, including the extra final-value call the wall tweens count on. The single non-ASCII character in an error message was replaced with `-`, leaving the file pure ASCII. No API or easing change; the whole project now passes strictness 3 with zero errors
